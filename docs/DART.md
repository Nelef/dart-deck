# DART 공시 RAG — 설계 (2026-10-16)

목표: 사업보고서를 근거로 찾아 **회사 분석 발표 자료**를 만들고, 말로 고친다. 근거마다 공시 접수번호를 단다.
법숲 실험에서 정한 기준(약 2만 5천 청크부터 벡터 DB 가 메모리 전수 검색보다 낫다)을 실제 규모에서 확인하는 것도 목표다.

## 1. 데이터 (OpenDART, 개인 인증키 — `.env` 의 `DART_API_KEY`, 커밋 금지)
- `corpCode.xml` → 회사 고유번호
- `list.json`(정기공시 · 사업보고서 `A001`) → 대상 회사의 최근 사업보고서 접수번호
- `document.xml` → 공시 원문(zip 안의 XML) → 장 · 절 단위 텍스트
- 정답용 정형 값: `fnlttSinglAcnt.json`(주요 재무 — 매출액 · 영업이익 · 당기순이익), `empSttus.json`(직원 수) 등
- 대상: 유가증권시장 시가총액 상위 약 100개사, 최근 1개 연도. 보고서 1건 ≈ 300~700 청크 → **약 5만 청크**(기준의 2배)

## 2. 청킹 · 임베딩 · 색인
- 장(Ⅰ. 회사의 개요 · Ⅱ. 사업의 내용 · Ⅲ. 재무에 관한 사항 …) → 절 → 문단 창(약 800자, 겹침 100자). 표는 행을 "항목: 값" 글로 펴서 넣는다
- 메타데이터: 회사명 · 종목코드 · 연도 · 장 · 절 · 접수번호(rcept_no)
- 임베딩: bge-m3(법숲과 같은 모델). NAS 는 2코어라 **이 맥에서 만들어** 벡터를 보낸다. 질의 임베딩만 서버에서
- 색인: Qdrant(같은 도커 네트워크 안 — 바깥에 열지 않음) + BM25, RRF 하이브리드. 회사 · 연도는 payload 필터

## 3. 평가 하네스 (사람이 고르지 않은 정답)
- 정형 API 값으로 질문을 자동 생성: "○○의 2025년 매출액은?" · "○○의 직원 수는?" 등 — 정답 = API 값
- 검색: 정답 값이 든 청크가 상위 k 안에 있나(hit@k · MRR), 회사 필터 유무 비교
- 답변: 숫자 일치(단위 환산 허용) · 근거 접수번호 인용 · 범위 밖(목록에 없는 회사) 거절
- 비교: 메모리 전수 검색 vs Qdrant HNSW(지연 · 정확도), 규모별(1만 · 2만 5천 · 5만) — 법숲 기준 재확인
- dev / test 분리, 설정 결정은 dev 로만

## 4. 에이전트 연결
- MCP 서버 `dart`: `dart_search(query, corp?, year?, k?)` · `dart_section(rcept_no, section)` · `dart_finance(corp, year)`
- DART Deck 의 Claude Code 실행에 MCP 를 붙인다 — 발표 자료에 넣는 숫자 · 사실은 도구 결과에서만, 각주에 접수번호
- 새 발표 자료 유형 「회사 분석 브리핑」: 개요 · 사업 구조 · 실적(3개년) · 리스크 · 요약

## 5. 데모
- 주인 계정으로 2~3개 회사 브리핑을 만들어 예시 덱으로 둔다(`DECK_DEMO_SAMPLES`)
- 방문자는 예시 덱을 AI 창이 열린 채로 받아 말로 고친다(세션마다 원본 사본, 부탁 횟수 상한)

## 6. 하지 않는 것
- 공개되지 않은 서버 · 모델 · 코드 · 데이터
- 투자 조언 — 화면 · 덱에 "공시 요약이며 투자 판단 근거가 아님"을 단다
